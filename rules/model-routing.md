# Model Auto-Routing [MUST]

## 1. Complexity Assessment [MUST]

收到用户请求后，先评估任务复杂度。

### 简单任务（当前 flash 模型直接做）
- 单文件小改动（≤30 行）
- 纯代码解释/阅读
- 搜索/查找符号
- 简单 bug 修复（原因明确）
- 格式化/命名调整

### 中等任务（flash 可做，Plan 模式先行）
- 2-3 文件协同修改
- 新增单个函数/类
- 重构单个模块
- 分析编译错误并修复

### 复杂任务（应切换 pro 模型）
- 跨 4+ 文件的多模块实现
- 架构级变更（新增/删除模块、改变分层）
- 引入新的设计模式或数据流
- 需要深度推理的算法实现
- 故障根因分析（多模块交互）

## 2. Routing Decision [MUST]

- 简单/中等 → 直接开始工作
- 复杂 → 告知用户：
  ```
  [MODEL] 此任务涉及 [具体原因]，复杂度较高，建议切换到 pro 模型。要切换吗？
  ```
- 不自动切换模型，需用户确认
- 模型路由决策直接关联 token 效率——简单任务用 flash 节省预算，复杂任务用 pro 避免反复试错，详见 `efficiency.md`

评估后给出简短预估：
"预计涉及 N 个文件，约 M 行改动，当前模型可完成。"

## 4. Model Info Source [MUST]

模型参数依赖 `/check-freshness` 的检查结果：
- 可用模型列表及能力
- 各模型上下文窗口大小
- 各模型 token 限制

本规则中具体的模型名称需随 freshness 检查结果更新。
